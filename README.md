# SHARE · 低延迟屏幕共享

## 下载体验

从 [GitHub Releases](../../releases) 下载 `screen-share-browser.zip` 并完整解压。Windows 双击启动服务.bat，在 Chrome 或 Edge 选择要共享的内容，观众用同网浏览器加入。


纯浏览器形态的屏幕共享工具。1 名演示者、最多 4 名观众（可自选 1~4 人），P2P 直连优先，无账号、不上传画面。主机用 Chrome/Edge 抓屏，观众用任意设备浏览器观看，零安装、零编译。

依据同目录 `产品设计.md` v1.0 与 `屏幕共享软件详细开发方案.md` 实现。Windows 原生客户端已于 2026-11-23 归档，见文末。

## 运行（浏览器版）

### 0. 双击启动（推荐）

直接双击项目根目录的 **`启动服务.bat`**，它会依次：

1. 检查 Node.js 18+。缺失、版本过低或损坏时，从 Node.js 官网下载 22.x 运行时并校验 SHA-256，安装到当前 Windows 用户的本地缓存。后续双击复用，无需 npm install。
2. 跑 `server/preflight.mjs` 做完整环境检测，窗口逐项打印 `[OK] / [提示] / [失败]`
3. 检测不通过 → **服务不启动**，窗口停在报错页，每项失败都给出「原因」和「处理」
4. 检测通过 → 以 `HOST=0.0.0.0` 启动服务，并**自动探测本机局域网 IP**（优先 192.168/10/172 私有网段，排除 VPN、Docker、WSL 等虚拟网卡）
5. 若端口上已有本服务在运行 → 不重复启动，直接打开页面；若被**其他程序**占用 → 明确报错，不再误判
6. 服务确认监听成功后自动打开 `http://localhost:3000` 网页端（无竞态）
7. 在窗口打印主机地址、邀请地址前缀、观众上限、房间 TTL

启动后：

- 主机访问 `http://localhost:3000`（**必须是 localhost**，抓屏需要安全上下文）
- 手机连同一 WiFi，打开主机页面上复制的邀请链接（自动带 `http://192.168.x.x:3000`）
- 停止服务：窗口内按 Ctrl+C，或直接关闭窗口

启动脚本用 `%~dp0` 定位项目，换机时请带上 `scripts/`。异地手机免装客户端观看，请双击 **跨网演示.bat**。该入口会检测并安装 Tailscale，引导主机登录，并使用当前设备的公网 HTTPS 地址生成邀请。详见[换机与免费跨网演示](docs/换机与免费跨网演示.md)。

**环境检测项**（也可单独运行 `node server/preflight.mjs` 做一次体检，零第三方依赖）：

| 检测 | 失败时显示的原因与处理 |
| --- | --- |
| Node.js 版本 | 低于 18 时提示安装 Node.js 18+（推荐 22 LTS）并给下载地址 |
| 项目文件完整 / 可读 | 列出缺失的具体文件名，提示拷贝完整目录（不要只拷 bat） |
| 配置解析 | `PORT`、`MAX_VIEWERS`、`ROOM_TTL_MS` 非法值，提示改成合法数值 |
| 邀请地址 | `PUBLIC_ORIGIN` 协议/格式错误；未探测到局域网 IP 时提示手机会打不开 |
| HTTPS 证书 | 变量不成对、文件不存在、PEM 损坏或公私钥不匹配，提示重新生成或改用 HTTP |
| 服务端口 | 区分「被其他程序占用」（提示换 `PORT` / `netstat` 查占用者）、「无权限」（换 1024 以上端口）、「HOST 地址不存在」（改 `0.0.0.0` / `127.0.0.1`） |

预检退出码：`0` 正常启动、`1` 环境有误（服务不启动）、`2` 本服务已在运行。启动瞬间若端口被抢或证书读取失败，`server/main.mjs` 另有 `[server] 启动失败（错误码）` 中文兜底日志；服务异常退出时 bat 显示退出码与常见处理，窗口不会闪退。

可用环境变量覆盖默认值：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `PUBLIC_ORIGIN` | 自动探测 | 邀请链接前缀；HTTPS 部署时显式指定 |
| `NO_BROWSER` | 未设置 | 设为 `1` 则不自动打开浏览器（自动化/无界面场景）；默认自动打开网页端 |

> 服务重启后所有房间码失效，务必用页面上新生成的码。

### 1. 本机开发（localhost）

```bash
node server/main.mjs
# 打开 http://localhost:3000
```

只在本机可用。

### 2. 局域网跨设备演示（HTTP，免证书，等价手动命令）

日常使用直接双击 `启动服务.bat` 即可；下面是等价的手动命令，便于理解原理或改端口。

主机需要安全上下文才能调用 `getDisplayMedia`，所以**主机必须访问 `localhost`**；观众端只用 `RTCPeerConnection` 接收流，不需要安全上下文，走普通 HTTP 即可。证书、TURN、HTTPS 全省掉。

```bash
# PUBLIC_ORIGIN 可省略：HOST=0.0.0.0 时服务会自动探测局域网 IP
HOST=0.0.0.0 PORT=3000 node server/main.mjs
```

- 主机：浏览器打开 `http://localhost:3000` → 开始共享 → 复制邀请链接（形如 `http://<主机局域网IP>:3000/join/XXXXXX`）。
- 观众：手机连同一路由器/热点的 WiFi，Chrome 打开邀请链接。
- `PUBLIC_ORIGIN` 决定邀请链接的域名，务必填主机在局域网里的真实 IP（`ipconfig` 查）。

要求：两台设备在同一网段、路由器未开 AP 隔离、主机防火墙放行 3000。**服务重启后所有房间码失效，必须用页面上新生成的码。**

### 2.5 跨网共享（虚拟局域网组网）

不同物理网络（例如主机在家、观众在公司）之间共享，**不需要公网服务器/域名/TURN**：用 Radmin LAN / Tailscale / ZeroTier 等组网工具把所有设备放进同一个虚拟局域网，再按上面的局域网方式使用即可。详见 `docs/虚拟局域网.md`。

核心要点：主机跑服务时把 `PUBLIC_ORIGIN` 设为主机的**虚拟 IP**（组网工具分配的，如 `26.x.x.x` / `100.x.x.x`）；主机用 `localhost` 打开，观众用虚拟 IP 访问。

也可用普通启动脚本启动服务，在主机首页展开 **邀请地址设置 → 手动填写**，输入 Radmin 网卡的地址和服务端口，例如 `http://26.x.x.x:3000`，再创建房间。地址会在当前浏览器中记住，房间链接和二维码共用该入口。恢复 **自动选择** 即使用启动时确定的入口。

### 3. 局域网跨设备演示（自签 HTTPS）

```bash
# 1) 生成证书（换成你主机的局域网 IP）
bash scripts/generate-cert.sh 192.168.1.10

# 2) 启动 HTTPS 服务
HOST=0.0.0.0 PORT=3000 PUBLIC_ORIGIN=https://192.168.1.10:3000 \
  TLS_CERT_FILE=certs/cert.pem TLS_KEY_FILE=certs/key.pem \
  node server/main.mjs
```

每台观看设备需先信任 `certs/cert.pem`（脚本输出末尾有各平台安装步骤）。然后：

- 主机访问 `https://192.168.1.10:3000`，点"开始共享"，选窗口，复制邀请链接。
- 观众打开邀请链接，或访问首页输入 6 位房间码。

### 4. 公网部署

需真实域名 + 可信证书（Let's Encrypt），并在部署端配置 TURN：

```bash
HOST=0.0.0.0 PUBLIC_ORIGIN=https://share.example.com \
  TLS_CERT_FILE=/path/cert.pem TLS_KEY_FILE=/path/key.pem \
  STUN_URLS=stun:stun.l.google.com:19302 \
  TURN_URLS=turn:turn.example.com:3478 \
  TURN_SHARED_SECRET=your-secret \
  node server/main.mjs
```

## 配置

全部通过环境变量，见 `server/config.mjs`：

| 变量 | 默认 | 用途 |
| --- | --- | --- |
| `HOST` / `PORT` | 127.0.0.1 / 3000 | 监听地址 |
| `PUBLIC_ORIGIN` | 自动 | 邀请链接前缀，必须所有参与者可达 |
| `TLS_CERT_FILE` / `TLS_KEY_FILE` | 空 | 成对提供则启用 HTTPS |
| `STUN_URLS` | Google 公共 STUN | 逗号分隔 |
| `TURN_URLS` | 空 | 跨网打洞失败时中转 |
| `TURN_SHARED_SECRET` | 空 | TURN 短期凭证密钥（HMAC） |
| `TURN_USERNAME` / `TURN_CREDENTIAL` | 空 | TURN 静态凭证（成对提供，优先于 HMAC） |
| `MAX_VIEWERS` | 4 | 全局观众上限（建房时可自选 1~4） |
| `ROOM_TTL_MS` | 7200000 | 房间有效期 2 小时 |

## 信令接口

同源 `/api/*`，详见 `屏幕共享软件详细开发方案.md` 第 5 节：

- `GET /api/bootstrap` — 建立会话
- `POST /api/rooms` — 建房，返回短码与邀请链接
- `POST /api/join` — 用短码加入
- `GET /api/rooms/{id}/events?peer=` — SSE 事件流（含有限重放）
- `POST /api/rooms/{id}/signal` — 转发 SDP/ICE
- `POST /api/rooms/{id}/state` — 暂停/声音/首帧状态
- `GET /api/rooms/{id}/session` / `/ice` — 恢复与 ICE 配置
- `POST /api/rooms/{id}/leave` / `/close` — 退出与关房

错误码统一格式：`{"code":"E-202","message":"...","retryable":false,"requestId":"..."}`。

## Windows 原生客户端（已归档，不再维护）

2026-11-23 将 `desktop/` 整个目录与 `docs/双形态规划.md` 移出主项目，冻结留存于同级目录 **`屏幕共享-桌面端归档/`**。主项目此后是纯浏览器版，不依赖 Rust / Tauri / MSVC Build Tools。

归档原因：原生端自行实现 WebRTC 数据面（codec 注册、PT 映射、关键帧间隔、ICE 状态机）反复出问题，而浏览器版 `getDisplayMedia()` + 内置 WebRTC 覆盖同一场景，画质与延迟更好，且零编译、可携带。详见归档目录内的 `README.md`。

## 已知边界

- P2P 拓扑上限约 4~5 人；本版观众可自选 1~4 人，人数是拓扑硬限制，选 4 人时对主机上行带宽要求较高。
- 系统音频仅 Chrome/Edge 分享标签页时可用。
- 移动端仅作观看端。
- 无账号、无鉴权：持有房间码即可观看，房间 2 小时后过期。
- 自签证书需设备手动信任；公网请换可信证书。
