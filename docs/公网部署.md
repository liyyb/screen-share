# 公网部署（跨网共享）

浏览器版代码已原生支持跨网，本文件说明如何把它部署到公网，让两台**不同网络**的设备互见屏幕。核心三件套：信令服务（HTTPS）+ STUN（默认已配）+ TURN（对称 NAT 兜底）。

## 1. 前提

- 一台有公网 IP 的 Linux 服务器（云服务器即可，1 核 1G 足够）
- 一个域名，并已把 A 记录解析到该服务器
- 服务器上装好 Docker + Docker Compose

## 2. 部署步骤

```bash
# 1) 把整个项目目录拷到服务器（至少需要 server/、public/、deploy/）
# 2) 进入 deploy 目录
cd deploy

# 3) 生成配置
cp .env.example .env

# 4) 改三处：
#    - .env 里的 PUBLIC_ORIGIN 换成你的域名（https://你的域名）
#    - .env 里的 TURN_SHARED_SECRET 换成强随机值
#    - turnserver.conf 里的 static-auth-secret 改成同一个值，realm 改成你的域名
#    - Caddyfile 里的 share.example.com 换成你的域名

# 5) 启动
docker compose up -d

# 6) 看日志确认
docker compose logs -f share caddy coturn
```

## 3. 防火墙 / 安全组放行

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 80 | TCP | Caddy 自动签发证书 |
| 443 | TCP | HTTPS 信令 + 静态资源 + SSE |
| 3478 | UDP/TCP | TURN 监听 |
| 49152–65535 | UDP | TURN relay 媒体 |

> 若你的服务器防火墙无法放行大段 UDP，可把 `turnserver.conf` 的 `min-port`/`max-port` 收窄（如 50000–50099），但 relay 能力随之受限。

## 4. 验证

1. 浏览器打开 `https://你的域名`，能看到 SHARE 首页（说明 HTTPS + 静态资源正常）。
2. 主机（任意网络）点「开始共享」，复制邀请链接。
3. 观众（用**手机蜂窝网络**，与主机不同网）打开邀请链接。
4. 看观众画面与主机状态条：
   - 显示「直连」→ 打洞成功，媒体不经过服务器
   - 显示「中继」→ 走了 TURN，说明打洞失败但 TURN 兜底生效（延迟略高）

## 5. 常见问题

| 现象 | 排查 |
| --- | --- |
| 首页打不开 | Caddy 证书未签发成功：`docker compose logs caddy` 看域名解析与 80 端口是否放行 |
| 能看到首页但连接失败 | 检查 TURN：`docker compose logs coturn`；若直连也不通，多为防火墙未放行 3478/relay 段 |
| 一直「正在连接」 | 双方都无法打洞且 TURN 不可用；核对 `.env` 的 `TURN_SHARED_SECRET` 与 `turnserver.conf` 的 `static-auth-secret` 一致 |
| 想改观众上限 | 在 `.env` 加 `MAX_VIEWERS=4` 后 `docker compose up -d` 重建 |

## 6. 无 Docker 的原生部署（备选）

同一套环境变量，直接跑 Node + 任意反向代理（nginx/caddy）+ coturn：

```bash
HOST=0.0.0.0 PORT=3000 \
PUBLIC_ORIGIN=https://你的域名 \
TURN_URLS=turn:你的域名:3478 \
TURN_SHARED_SECRET=你的密钥 \
node server/main.mjs
```

反向代理需关闭 SSE 响应缓冲（nginx 用 `proxy_buffering off`，caddy 用 `flush_interval -1`）。
