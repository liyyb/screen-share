# 换机与免费跨网演示

目标是在一台 Windows 电脑上演示，异地 Android 或 iPhone 直接用浏览器扫码观看。电脑运行本项目，Tailscale Funnel 提供 HTTPS 网页入口。浏览器优先通过 WebRTC 直连，直连失败时可使用有免费额度的托管 TURN。电脑在共享期间须保持联网、唤醒；无需购买域名或租云服务器。

## 1. 从原电脑带走什么

复制根目录的 **启动服务.bat**、**跨网演示.bat** 和完整的 **scripts/**、**server/**、**public/**。建议同时带上 README 和本说明。二维码编码器在 public 里，不能漏拷。临时测试用的浏览器配置、截图、旧设备私钥都无需带走。若使用 TURN，请单独准备服务商的中继地址、用户名和密码，勿随公开分发的项目打包。

演示主机建议使用 Windows 10/11 x64 或 ARM64、Edge 或 Chrome。手机仅使用浏览器。新电脑第一次自动安装需要能访问官方下载站；学校机房如果限制安装网络驱动，需要管理员协助批准 Tailscale 安装。已装好 Node 的电脑可离线启动同网模式。

## 2. 双击哪个脚本

| 使用场景 | 入口 | 脚本实际执行的操作 |
| --- | --- | --- |
| 教室同网预演 | 启动服务.bat | 检测 Node、完整文件、配置、证书和端口，默认在 3000 启动；打开 localhost，复制/扫码地址用本机物理局域网 IP |
| 手机用蜂窝网观看 | 跨网演示.bat | 检测 Node 与 Tailscale。根据当前电脑的 Tailscale DNS 名确定 PUBLIC_ORIGIN，在回环地址默认 3001 启动 Node；健康检查成功后，在窗口前台运行 Funnel |

Node 优先复用 PATH 中可运行的 18+ 版本，再查当前用户缓存。两者均不可用时从 nodejs.org 下载对应架构的 22.x node.exe，校验官方 SHA-256 后放入 `%LOCALAPPDATA%\SHARE\runtime`。Tailscale 在跨网模式下优先通过 WinGet 安装；无 WinGet 时下载安装官方签名的 Windows 安装程序。Windows 的安装授权、账号登录、首次 Funnel 授权由设备使用者完成。

## 3. 第一次让两个不同网络连通

1. 先在演示电脑双击 **跨网演示.bat**。首次按提示登录自己的 Tailscale 个人账号。启用 MagicDNS、HTTPS 和该设备的 Funnel 权限；若窗口打印授权网址，使用主机浏览器打开并确认。若提示批准后需重试，重新双击跨网入口。
2. 等窗口出现 **Available on the internet** 及类似 `https://电脑名.网络名.ts.net` 的地址。以窗口实际输出为准。把这个完整地址复制到**主机 Edge/Chrome**，进入首页。该地址是公网入口，获得地址的人可访问应用。演示结束后关闭 Funnel。
3. 选择 **流畅 720p30**、1 名观众，开始共享一个有滚动文字的窗口。检查复制链接以相同的 HTTPS 域名开头，并包含 `/join/六位房间码`。不同电脑的域名可能不同，每次演示使用本次生成的链接。
4. 手机关闭 Wi-Fi 和 VPN，保留 4G/5G。用相机扫描“复制链接”右边的二维码，在系统浏览器打开；若提示播放，点按一次。主机滚动文字，手机应看到变化；打开详情记录实际路径、帧率、码率和 RTT。
5. 点暂停、恢复、停止，观察手机状态同步。验完后在启动窗口按 **Ctrl+C**，使前台 Funnel 结束并让脚本清理本次启动的 Node 子进程。下次重新创建房间。

Funnel 提供网页、API 和 SSE 信令的公网入口。是否能直连还取决于两端网络；一台手机成功只验证这组网络。Funnel 官方列为 Beta，个人免费计划可使用，观众无需 Tailscale 账号。[Funnel 说明](https://tailscale.com/docs/features/tailscale-funnel) · [个人计划](https://tailscale.com/docs/account/manage-plans/free-plans-discounts)

## 4. 配置零付费预算的 TURN 兜底

在手机能打开房间却长时间等画面、或需要验证运营商限制场景时，配置托管 TURN。此项目已经有 TURN 地址和凭证接口。下面采用 Metered 的普通 TURN 免费试用，官方标注每月 **500 MB**，进出流量合计，无需信用卡。使用免费档，设置额度，活动前检查剩余用量。[免费计划](https://www.metered.ca/stun-turn)

1. 在服务商后台创建独立演示项目和 TURN credential。给项目设置自定义月配额，例如 **400 MB**，触及配额时选择 **Disable credentials**。该配额是本方案的演示预算。[配额与停用设置](https://www.metered.ca/docs/turn-rest-api/project/index/)
2. 复制后台给出的完整 TURN URL、用户名和凭证。保留服务商实际列出的端口、传输参数及可用的 `turns:` 地址。这里用的是浏览器建连所需的 TURN 凭证，管理后台 API key 仅供服务商管理接口使用。
3. 停止正在运行的跨网演示，在项目目录打开 PowerShell，按下面的模板设置当前会话环境并启动。把示例域名和用户名换成后台值。密码在提示时输入，避免写入命令历史或项目文件。

```powershell
$env:TURN_URLS = 'turn:实际主机:3478?transport=udp,turns:实际主机:443?transport=tcp'
$env:TURN_USERNAME = '实际中继用户名'
$secret = Read-Host 'TURN credential' -AsSecureString
$env:TURN_CREDENTIAL = [System.Net.NetworkCredential]::new('', $secret).Password
& '.\跨网演示.bat'
```

这些设置仅对该 PowerShell 及子进程生效；从资源管理器另行双击不会继承。日常免输入可在这台演示机的 Windows“用户环境变量”中设置相同三项，重新打开启动程序。共享电脑更适合临时设置；演示后关闭该终端、在服务商后台撤销演示凭证。

以每人约 2 Mbps 估算，一个观众全程中继，按进出双计约 **30 MB/分钟**，400 MB 约 13 分钟。实际码率、协议开销和观众数会影响结果。演示时间较长可选 480p15，并观察后台用量。

## 5. 验证 TURN 真正传送了画面

使用刚才设置凭证的同一 PowerShell，停止旧演示，再执行：

```powershell
$env:SHARE_RELAY_ONLY = '1'
& '.\跨网演示.bat'
```

新建房间，让手机用蜂窝网扫码。**通过条件是有连续变化的画面，详情显示“中继”，暂停和恢复成功。** 只看到首页、拿到 relay 候选、或界面显示“检测中”都不足以证明媒体确实经过中继。若失败，记录错误码和手机端状态，核对 TURN 凭证、URL、配额和 TCP/TLS 路径。

验证完后按 Ctrl+C，在同一终端恢复正常演示：

```powershell
Remove-Item Env:SHARE_RELAY_ONLY -ErrorAction SilentlyContinue
& '.\跨网演示.bat'
```

## 6. 演示现场排查

| 现象 | 检查和处理 |
| --- | --- |
| 换机后脚本报缺少文件 | 按第 1 节重新复制，保留原目录层次。项目文件要从原项目恢复 |
| Node 下载失败或校验不符 | 检查到 nodejs.org 的 HTTPS 访问、系统时间和代理，重新双击；也可事先安装官方 Node LTS |
| Tailscale 安装／登录失败 | 查看 Windows UAC、网络驱动安装权限和账号登录状态。已安装时在开始菜单打开 Tailscale，登录后重试 |
| Funnel 无法开启或域名无法访问 | 检查 MagicDNS、HTTPS、Funnel 策略和终端实际输出；手机用蜂窝网络直接打开公网首页，再测加入房间 |
| 二维码仍为 192.168.x 或 26.x | 当前是局域网实例或旧房间。通过跨网入口打印的 HTTPS 首页重新建房 |
| 跨网端口已占用 | 正在演示时复用原窗口；如是其他程序，在 PowerShell 用 `$env:PORT='3011'` 后启动跨网脚本。脚本将同一端口传给 Funnel |
| 能打开页面却无法入房 | 确认邀请来自仍在运行的实例，重启后旧房间失效；检查主机和手机的地址栏是否为同一公网来源 |
| 能入房却没有首帧 | 先点按播放，确认主机正在采集；按第 5 节强制中继。强制中继失败时核对凭证、额度、网络和手机浏览器 |
| 首次成功，切网后黑屏 | 分别记录 4G/5G、其他 Wi-Fi、返回前台时的路径和错误码。重试并确认另一名观众仍在观看 |

建议最终各用一台 Android Chrome、iPhone Safari 做一次普通连接和一次强制中继，记录日期、电脑与手机网络、实际路径及首帧时间。RTT 表示网络往返时间，画面延迟需要独立实测。
